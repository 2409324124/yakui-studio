# Shared project CLI protocol

The CLI is an execution tool for people and agents. All commands use the running local workbench; they do not need a separate terminal UI or model token. Use `--url http://127.0.0.1:PORT` or `YAKUI_STUDIO_URL`; default port is 5240. Never guess which instance owns the user's project.

## Read, edit, export

```sh
yakui-studio project read --url http://127.0.0.1:5240 > current.json
yakui-studio project selection --url http://127.0.0.1:5240
yakui-studio project apply --file edit.json --url http://127.0.0.1:5240
yakui-studio project export edited.mid --url http://127.0.0.1:5240
```

Read returns `{project,selection,canUndo,canRedo}`. Build edits from these actual IDs and revision. Example template (replace placeholders with read results):

```json
{
  "projectId": "PROJECT_ID_FROM_READ",
  "baseRevision": 7,
  "operationId": "NEW_UNIQUE_ID",
  "selection": {"clipId":"CLIP_ID","noteIds":["NOTE_ID"],"start":0,"end":4,"revision":7},
  "operations": [
    {"type":"updateNotes","clipId":"CLIP_ID","noteIds":["NOTE_ID"],"delta":{"midi":12}}
  ]
}
```

`selection` is an explicit constraint on the edit; include the current browser selection for selected-only requests. Omitting it allows a whole-project edit and is appropriate only when the user's requested scope allows that. Stored selection is not automatically applied to every operation. An operation list is atomic: invalid/out-of-scope notes reject the whole request. Repeating the exact request with the same operationId is idempotent; use a new ID for a different edit. On 409 conflict reread and reevaluate, never just update the version number to force a stale edit through.

## Operation fields

| type | Required fields |
|---|---|
| renameProject | title; no selection constraint |
| updateTrack | trackId, patch: name/gain/pan/wave/duty/mute/solo |
| updateClip | clipId, patch: start/name |
| updateNotes | clipId, noteIds; exactly one of patch or delta, keys start/duration/midi/velocity |
| replaceNotes | clipId, start, end, notes; optional noteIds and summary |
| addSection | section: id/name/start/end |
| updateSection | sectionId, patch: name/start/end |
| deleteSection | sectionId |

`replaceNotes.notes` entries are `{start,duration,midi,velocity}`, with starts relative to the clip. Empty/omitted noteIds selects notes whose starts fall in the specified range. New note IDs are generated by the service. Track wave choices are pulse/triangle/sine/sawtooth/noise; gain and velocity ranges follow project validation. A selected track settings edit requires a full-track selection, not a partial clip/note selection.

Clip selection uses local beats: `{clipId,noteIds,start,end,revision}`. General selection uses absolute quarter-note beats: `{trackIds?,clipIds?,sectionIds?,start,end}`. Section metadata can describe song passages; it does not replace existing clips. For creating an entirely new track/arrangement, generate a complete valid project and explicitly import it; granular addTrack/addClip operations are not exposed yet.

## Import, undo, selection

```sh
yakui-studio project import input.mid
yakui-studio project import project.json
yakui-studio project export backup.json
yakui-studio project undo --project PROJECT_ID --revision CURRENT_REVISION
yakui-studio project redo --project PROJECT_ID --revision CURRENT_REVISION
```

Import replaces the current project; export a backup first when preserving user work. Import supports SMF0/1 and JSON. Export .mid/.midi or .json. MIDI controllers and program events are retained for export but not fully executed by the chip synth.

`project selection --file selection.json` accepts `{projectId,baseRevision,selection}` (selection may be null). It changes shared selection without incrementing project revision. Current browser selection may update it again as the user interacts. The browser polls external project edits and stops old playback snapshots before showing the new revision.

## Process ownership

Only one service may own a workspace directory. Start separate projects with `--workspace PATH`; do not start another service on the same directory just because the port differs. Normal shutdown releases the directory lock. After a crash, confirm the PID named in the lock error has stopped before removing the specified lock. Do not delete an active owner's lock.
